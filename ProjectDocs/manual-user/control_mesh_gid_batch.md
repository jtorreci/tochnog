# control_mesh_gid_batch

Mesh the [mesh_gid_*](mesh_gid.md) geometry with GiD in batch mode (manual Professional
6.200).

## Syntax

```
control_mesh_gid_batch  index  switch
```

With `-yes`, at the start of control index `index` Tochnog:

1. writes the GiD batch file `GidMeshBatch.bch` in the working directory from the
   `mesh_gid_*` records;
2. if `gid` is on the PATH, runs `gid -n -b GidMeshBatch.bch`. The tochnog.gid problem type
   writes the mesh to `mesh_gid.gid/mesh_gid.dat` (records `node`, `element`,
   `element_group` and `geometry_list` 1 ... 30). Tochnog copies it to `<index>.dat` and
   removes `GidMeshBatch.bch` and the `mesh_gid.gid` directory.

This happens before [control_input](control_input.md) of the same index, so
`control_input index -yes` reads the mesh just generated. With `-no` nothing is done.

```
echo -yes
number_of_space_dimensions 2
end_initia
mesh_gid_point_coord 1 0. 0.
mesh_gid_point_coord 2 1. 0.
mesh_gid_point_coord 3 0. 1.
mesh_gid_point_coord 4 1. 1.
mesh_gid_line_point 1 1 2
mesh_gid_line_point 2 2 4
mesh_gid_line_point 3 4 3
mesh_gid_line_point 4 3 1
mesh_gid_surface_line 1 1 2 3 4
mesh_gid_surface_element_group 1 1
mesh_gid_size 0.1
control_mesh_gid_batch 10 -yes    ( writes GidMeshBatch.bch, gid makes 10.dat )
control_input 10 -yes             ( reads the mesh in 10.dat )
end_data
```

## Requirements

- GiD (CIMNE) with its executable directory in PATH.
- The `tochnog.gid` directory of the Professional distribution
  (`partners/gid/tochnog.gid`) in the GiD problemtypes directory.

## Without GiD

If `gid` is not on the PATH, `GidMeshBatch.bch` is kept, a warning is printed and the run
continues:

```
Warning: control_mesh_gid_batch 10: gid is not on the PATH. The GiD batch file GidMeshBatch.bch is kept and 10.dat is not generated by GiD.
```

You can then run `gid -n -b GidMeshBatch.bch` yourself (or open the file in GiD) and copy
`mesh_gid.gid/mesh_gid.dat` to `<index>.dat`. `control_input` reads `<index>.dat` only when
it exists.

If gid runs but does not write `mesh_gid.gid/mesh_gid.dat`, Tochnog prints the message of the
Professional (`Error, CONTROL_MESH_GID_BATCH failed to generate a mesh.` and four hints),
keeps the batch file and continues.

## The batch file

The file is byte-equal to the one the Professional 02-08-2026 writes (its examples
`test/other/mesh_gid_1..8.dat` and 2D/3D probes). Commands are grouped by type, not in input
order: points, lines, circles, arcs, rectangles, cylinders, spheres, `Collapse Points`,
surfaces, volumes, conditions, `Meshing Generate <mesh_gid_size>`. The file has no final
newline.

## Differences with the Professional 02-08-2026

- Without gid the Professional prints `Error, CONTROL_MESH_GID_BATCH failed to generate a
  mesh.` and still ends with exit code 0; GNU prints a warning naming the kept file and also
  ends normally.
- The examples of manual 6.200 write `control_mesh_gid 10 -yes`; the Professional rejects that
  name. The record is `control_mesh_gid_batch`.
- Input errors in the `mesh_gid_*` records end the Professional with exit code 0; GNU ends with
  exit code 1.
- A mesh-only model without unknowns (as the Professional examples) reads the generated mesh
  with `control_input` too (test `control_mesh_gid_batch3`).
