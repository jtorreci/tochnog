# mesh_gid (GiD batch meshing)

`control_mesh_gid_batch` (manual Professional 6.200) and the 36 `mesh_gid_*` records
(6.818-6.853). User pages: [control_mesh_gid_batch](../manual-user/control_mesh_gid_batch.md),
[mesh_gid](../manual-user/mesh_gid.md).

| What | Where |

## Design

- The oracle is the Professional 02-08-2026: the expected `<test>.bch` files are the
  Professional output for the same input, compared with `cmp` in a scratch copy. The fixture
  examples `mesh_gid_1..8` of the distribution are also byte-equal.
- `mesh_gid_check` validates everything first (missing `mesh_gid_size`, object size records,
  concentration range, structured nel count, condition index ranges and gaps, dimension) and
  stops through `db_error`. The Professional writes a partial file and stops on the first bad
  record; GNU never leaves a partial batch file.
- `mesh_gid_write` keeps running counters of GiD points, lines, surfaces and volumes. The
  per-object increments are listed in the header comment of mesh_gid.cc and in the user page.
  Record indices are never written; references (`line_point`, `surface_line`,
  `volume_surface`, conditions) are written as given, because they are GiD numbers.
- Numbers are written with `%g` (6 significant digits), as the Professional.
- gid is looked up in PATH with `access(X_OK)` (gid.exe / gid.bat on Windows), then run with
  `system("gid -n -b GidMeshBatch.bch")` in the working directory. Success is decided by the
  existence of `mesh_gid.gid/mesh_gid.dat`, not by the exit code of gid.
- Echo report (`generated by MESH_GID_...`, `assigned by ...`) follows the Professional text,
  printed only with `echo -yes`.

## Gotchas (byte-exactness)

- `CreateAlwaysNewPoint 1` precedes each non-empty group (points, each object type, surfaces,
  volumes); `CreateAlwaysNewPoint -2` precedes the lines. There is no header
  `CreateAlwaysNewPoint` when there are no points.
- Trailing spaces: point coordinates (`x y 0.0 ` in 2D, `x y z ` in 3D), object headers
  (`CirclePNR ... 0 0 1 `, `Rectangle `, `Cylinder ... `, `Sphere ... `), object group
  surfaces/volumes (`1 `), structured size line lists and volume surface lists.
- Group of a user surface: `GROUP_g Surfaces` with `<n>` (no trailing space); of an object:
  `<n> ` (trailing space).
- Hollow circle: two `Create Arc` with space-separated points; `mesh_gid_arc_coord`: commas
  (`x,y,0.0`).
- Hollow rectangle / cylinder / sphere: `Delete Surface|Volume` with counter+1 followed by an
  empty line; the counter is not incremented.
- `mesh_gid_line_size` and `mesh_gid_line_structured_size` write the same command.
- Surface element: triangles for tria3/tria6 (default in 2D), quadrilaterals for quad and hex
  types, nothing for tet4 (default in 3D), `Model(QuadraticType) 1` for tria6, quad8, tet10,
  hex20 and `2` for quad9, hex27.
- `mesh_gid_volume_element_group` writes `Mat Assign <group> Volume`: Professional-suspect,
  reproduced byte by byte.
- The file ends with `Mescape Quit\nNo` without newline; .gitattributes marks `*.bch -text`.
- Circles are skipped in 3D (the Professional writes `CreateAlwaysNewPoint 1` without newline
  and no circle).
- `input_control_input` (input.cc) creates the `node_start_refined` records of the nodes it
  reads also when `nuknwn==0` (fixed with this feature: before, a mesh-only model stopped with
  "Error detected for data item : node_start_refined"). `control_mesh_gid_batch1` declares
  dofs, `control_mesh_gid_batch3` has none.

## Tests

- `mesh_gid_2d1`, `mesh_gid_3d1`, `mesh_gid_objects1`, `mesh_gid_elements1`: `cmp` with the
  Professional `.bch`, run without gid (`PATH=/usr/bin:/bin`), warning checked.
- `mesh_gid_error1..5`: expected input errors.
- `control_mesh_gid_batch1`: a fake `gid` script written by build_safe.sh into the scratch
  directory (never committed) writes `mesh_gid.gid/mesh_gid.dat`; checks `10.dat`, removal of
  the batch file and of `mesh_gid.gid`, and the target on node 5 read by `control_input`.
- `control_mesh_gid_batch2`: `-no` writes no batch file.
