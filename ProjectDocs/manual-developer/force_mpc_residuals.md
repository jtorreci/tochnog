# post_element_force / mpc residuals — force16, force17, mpc9 (dev/fmpc)

Developer notes for the three single-test residuals of the 2026-09-08
sprint. All Professional numbers measured on the 25-10-2023 binary
(print-enabled probes; the corpus inputs keep `control_print` commented).

## mpc_node_number — when the Professional condenses (CLOSED: mpc9)

The slave equilibrium row is not simply dropped. The Pro applies the
§16 energy-consistent elimination to a tie when the slave dof AND every
master dof are FREE unknowns:

| record class | slave free | masters free | semantics |
|---|---|---|---|
| generated by mpc_linear_quadratic | — | — | condensed (DIAG §16) |
| generated by bounda -veln (mpc_from_bounda) | yes | — | condensed; a directly bounda'd slave dof is INERT (the direct prescription wins, measured at the -veln inflow corner) |
| explicit user mpc_node_number | yes | yes | **condensed (measured: mpc9, v2 = 5/11, condensed diagonal K22+K33 = 11/6)** |
| explicit user mpc_node_number | any | any bounded | value-constrained (measured byte-identical: mpc1 = Dirichlet master, mpc8 = bounda'd slave) |
| generated by mpc_element_group | — | — | value-constrained in the GNU fork (see force16 below) |

Implementation notes (mpc.cc):

- the eligibility inputs are evaluated PER PASS; the slaves applied
  through an eliminated tie join the per-pass bounded-flag clearing list
  (formerly -veln only). Without the clearing, the flag set by pass k
  disqualifies the tie at pass k+1 and the elimination is lost after the
  first iteration.
- the mpc_element_group generated records carry no marker; the
  explicit-user class excludes them by their fingerprint index range
  (MPC_ELEMENT_GROUP_MESH_FINGERPRINT) — measured requirement, see
  force16.

## post_element_force_force / post_element_force_inertia (CLOSED: force17)

1D semantics measured on the Pro: with either switch -yes the result is
the sum over the group's elements of the LUMPED body-force shares of
their nodes:

```
share_i = dens * sum_ip wrule[0][ip] * 2*|jac| * N_ip(i)   (initial geometry;
                                            = rho*L/2 per bar2 node)
result += share_i * (force_gravity . dir_n)      (_force  -yes)
result -= share_i * (acceleration . dir_n)       (_inertia -yes)
```

- the acceleration a = (v − v_prev)/dt needs the PREVIOUS-step velocity:
  post_element_force_calculate runs AFTER the step-close
  db_version_copy(NEW→NORMAL), so calcul_force.cc keeps a snapshot of the
  velocity dofs across calls; the first call assumes zero initial
  velocities (true for every corpus user; force17 is the only one).
- the elastic internal forces of a complete element are self-equilibrated
  (they cancel in the per-element nodal sum), so the result carries no
  elastic term and the section device is not combined with the switches.
- force17 checks 10 − (0.5·v1 + 0.5·v2) = 9.931723274805 (13 digits
  exact) and its equality with node_rhside(3).
- quadrature warning: interpolation_polynomial returns DERIVATIVES in px
  and VALUES in hx — the shares use hx.

## force16 — measured Pro mechanism, closure bounded (RUNFAIL, diagnosis)

The Pro field is the CONDENSED state of the mpc_element_group tie
v3 = v2 (closed form, momentum matrix M/dt + K, m = 0.5/node,
G = 4.905/node, v1 = 1 Dirichlet):

```
value-constrained (GNU): 1.5 v2 = G + k1 v1   -> v2 = 3.93667  (GNU output)
condensed (Pro):         3 v2 - v4 = 2G+1 ; 1.5 v4 - v2 = G
                         -> v2 = 1056/175 = 6.0342857 (Pro output)
post = sigma*A = v2 - v1 = 5.034285714286 = the corpus target
```

The eg-range condensation was prototyped and measured: it reproduces the
Pro field exactly (rc=0) and also closes mpc6, but it breaks the mpc7
corpus target (±1e-8) because the GNU staggered map with the elimination
has an intrinsic ~1e-8/iteration inconsistency (pre-existing §16
behaviour; mpc3 shows the same 3e-9 residual at its 2-iteration cap and
passes only because its targets are ±1e-3). mpc7's loop is capped at 2
iterations, so the condensed solve stops 1.19e-8 from the exact state —
1.9e-9 outside the target.

UNCLOSABLE HERE: the map inconsistency lives in the solve/element
interplay (the folded slave row's sigma feedback lag; so.cc /
so_bicg.cc / materi.cc), not in the tie bookkeeping. Once fixed, the
closure is the `in_eg_range` activation in mpc.cc (the test is already
written, kept as an explicit exclusion) plus reverting the exclusion.
